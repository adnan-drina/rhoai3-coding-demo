# OpenShift ingress, Routes and Gateway API

Thin skill: repo decisions and pitfalls here, product behavior in the linked
OpenShift Container Platform 4.22 sections. Detailed record:
`gitops/stages/040-governed-models-as-a-service/040-gateway-governance/README.md`.

## When to use

- A change touches `040-gateway-governance/gateway/` or a `kind: Route` manifest.
- The MaaS endpoint is unreachable, answers on the wrong host, or long
  streams are cut at a fixed interval.
- The default ingress certificate or the ingress load balancer changes.

## Repo decisions

| Decision | Where in Git | Official section |
|---|---|---|
| One Gateway API `Gateway`, `maas-default-gateway` in `openshift-ingress`, class `data-science-gateway-class` (created by OpenShift AI, not by this repo); HTTPRoutes are generated by the MaaS and KServe controllers, none in Git | `gateway/gateway.yaml` | [Configuring Gateway API][gw], [Enabling Gateway API][gw-enable] |
| Listener hostnames are placeholders in Git; `deploy.sh` reads the default IngressController domain and passes a Kustomize patch to the `040-gateway-governance` Application, so Git stays cluster-neutral | `stages/040-governed-models-as-a-service/deploy.sh` | [Gateway listeners][gw-listeners] |
| Listeners terminate TLS with the cluster's cert-manager wildcard Secret `cert-manager-ingress-cert` in the same namespace (no ReferenceGrant, renewals reach Envoy); `preflight.py` requires IngressController `default` to use that certificate | `gateway/gateway.yaml`, `stages/040-governed-models-as-a-service/preflight.py` | [Edge TLS for HTTPRoutes][gw-edge], [Replacing the default ingress certificate][ingress-cert] |
| Gateway load balancer idle timeout 3600 s through `spec.infrastructure.annotations` (`service.beta.kubernetes.io/aws-load-balancer-connection-idle-timeout`) | `gateway/gateway.yaml` | [Gateway address assignment][gw-address] |
| Fixed ClusterIP Service `maas-gateway-internal` (`172.30.250.250`) so workspaces reach the gateway in-cluster through a devfile `hostAlias`, keeping SNI and host matching | `gateway/service-maas-gateway-internal.yaml` | none: repo measurement recorded in the manifest and README |
| Gateway proxy resources set through the `parametersRef` ConfigMap (requests 1Gi, limit 2Gi) | `gateway/configmap-maas-gateway-resources.yaml` | [Gateway API implementation specifics][gw-impl] |
| Gateway pod boundary is an AdminNetworkPolicy (priority 40), because the Ingress Operator's allow-all NetworkPolicy cannot be narrowed by more NetworkPolicies; `validate-gateway-boundary.sh` checks it | `gateway/adminnetworkpolicy-maas-gateway.yaml`, `stages/040-governed-models-as-a-service/validate-gateway-boundary.sh` | [Admin network policy][anp] |
| Plain Routes use `termination: edge` with `insecureEdgeTerminationPolicy: Redirect` and the default router certificate; the Stage 070 Git server Route sets `haproxy.router.openshift.io/timeout: 600s` | `gitops/stages/060-agent-runtime-and-agentops/060-agent-tools/hosting/route-rw.yaml`, `gitops/stages/070-advanced-app-platform/070-sonarqube/generated/route-sonarqube.yaml`, `gitops/stages/070-advanced-app-platform/070-gitlab/route.yaml` | [Edge route][route-edge], [Route timeouts][route-timeout] |
| Default IngressController Classic ELB idle timeout raised to 1h as a documented cluster-local step, not GitOps | `docs/OPERATIONS.md` (Bootstrap) | [Classic Load Balancer timeouts on AWS][elb] |

Paths starting with `gateway/` are under
`gitops/stages/040-governed-models-as-a-service/040-gateway-governance/`.

## Procedure

1. Change the Gateway, Service or policy in Git only; the hostnames come from
   `deploy.sh`, never from an edited manifest.
2. Deploy and validate: `./stages/040-governed-models-as-a-service/deploy.sh`,
   then `./stages/040-governed-models-as-a-service/validate.sh` and
   `./stages/040-governed-models-as-a-service/validate-gateway-boundary.sh`.
3. Read-only checks, after the OpenShift safety guard in `AGENTS.md`:

   ```bash
   oc get gatewayclass data-science-gateway-class
   oc get gateway maas-default-gateway -n openshift-ingress -o yaml
   oc get httproute -A
   oc get svc maas-gateway-internal -n openshift-ingress
   oc get ingresscontroller default -n openshift-ingress-operator -o jsonpath='{.status.domain}{"\n"}'
   ```

## Pitfalls

- A new upstream for the gateway (another model namespace or port) needs an
  allow rule in `maas-gateway-boundary` first, or traffic is denied.
- Responses cut at exactly 60 s point to a load balancer idle timeout; silent
  streams cut after several minutes on the public path are the reason for the
  in-cluster Service (`docs/TROUBLESHOOTING.md#maas-gateway-holds-a-response-open-until-the-client-times-out`).
- Listener without the cluster domain or a non-admitted route:
  `docs/TROUBLESHOOTING.md#maas-gateway-is-not-reachable`.
- Proxy memory pressure during long sessions:
  `docs/TROUBLESHOOTING.md#maas-gateway-approaches-its-memory-limit`.
- Listener conflicts and status conditions are reported on the Gateway, not on
  the HTTPRoute alone ([Gateway status conditions][gw-status]).
