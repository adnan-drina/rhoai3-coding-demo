## Captured Content

- Lifecycle: discovery (name + description only, ~100 tokens) →
  activation (full body) → execution (resources on demand).
- Format: directory structure, six frontmatter fields with exact
  constraints, name validity rules, minimal example, file-reference
  depth rule, `skills-ref validate`.
- Sourcing: the generic-LLM-generation pitfall; extract-from-hands-on-task
  and synthesize-from-artifacts methods; refine-with-real-execution and
  reading execution traces.
- Context economy: add-what-the-agent-lacks test, coherent units,
  moderate detail, progressive disclosure with explicit load triggers.
- Control calibration: freedom vs prescription by fragility, defaults not
  menus, procedures over declarations.
- Six instruction patterns: gotchas, output templates, checklists,
  validation loops, plan-validate-execute, bundled scripts.

## Why this matters to this repo (verified)

The Quickstart states VS Code "looks for skills in `.agents/skills/` by
default" — this repo's canonical skill path IS the standard's default
discovery location, so spec conformance is operationally relevant here,
not merely aspirational. Hermes skills separately declare compatibility
with this standard (see `hermes-skills`).

## Source Boundaries

Format + content authoring live here. The `description` field and its
triggering evals → `agentskills-descriptions`; output-quality evals →
`agentskills-evaluation`; this repo's own taxonomy (skill-group prefixes,
`.agents/` layout, tool bridges) → `maintain-rules-and-skills`; Hermes
seat-side R-SK law → the stage 080 scaffold.

## Repo conformance baseline (2026-08-13)

`scripts/validate-skills.py --all` over 213 skills: **14 errors, 0
warnings**. All 14 are `rhoai-*` descriptions exceeding the 1024-char
limit (1025–1367 chars), generated by
`project-red-hat-doc-skill-authoring` before this standard was adopted:
distributed-inference-llmd, distributed-workload-workflows,
distributed-workloads, evaluation, guardrails-safety, llama-stack,
mlflow, model-customization-training, model-deployment, model-evaluation,
model-management-monitoring, model-serving-platform, monitoring-trustyai,
workbenches-custom-images. Every other skill (including all `hermes-*`
and these three) passes name, description, line-count, and reference-depth
checks. Root cause is the generating workflow's lack of a length
constraint — fixing the descriptions without fixing that skill would
regress on the next generation run.
