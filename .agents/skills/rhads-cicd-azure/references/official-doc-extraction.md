# Official Doc Extraction

Use this extraction to keep Azure Pipelines CI/CD integration content grounded
in official RHADS-SSC 1.9 sources.

## Product Overview

Red Hat Advanced Developer Suite - software supply chain (RHADS-SSC) integrates
with Azure Pipelines to perform essential security tasks: vulnerability
scanning, image signing, and attestation generation. Pipelines require secrets
stored in Azure variable groups to connect with external tools.

## Automated Setup

The `ci-set-org-vars.sh` script, packaged in the `tssc-cli` image, creates a
variable group with all required variables and secrets:

```bash
bash-5.1$ ./scripts/ci-set-org-vars.sh -b azure -p <devops_project>
```

The script creates a variable group named `tssc` by default. Override with `-g`:

```bash
bash-5.1$ ./scripts/ci-set-org-vars.sh -b azure -p <devops_project> -g <custom-name>
```

## Secrets (Masked in UI and Logs)

### Image Registry and GitOps Secrets

| Variable | Description |
|----------|-------------|
| `IMAGE_REGISTRY_PASSWORD` | Password for accessing your container image registry |
| `GITOPS_AUTH_PASSWORD` | Token the system uses to update the GitOps repository for newly built images |

### ACS and SBOM Secrets

| Variable | Description |
|----------|-------------|
| `ROX_API_TOKEN` | API token for accessing the ROX server |
| `COSIGN_SECRET_PASSWORD` | Password for Cosign signing key |
| `COSIGN_SECRET_KEY` | Private key for Cosign |
| `TRUSTIFICATION_OIDC_CLIENT_SECRET` | Client secret for Trustification Bombastic API OIDC auth |

All credentials are already Base64-encoded from `private.env` and do not
require additional encoding.

## Variables (Unmasked)

### Image Registry and GitOps Variables

| Variable | Description |
|----------|-------------|
| `IMAGE_REGISTRY_USER` | Username for accessing your container image registry |
| `GITOPS_AUTH_USERNAME` | (Optional) OpenShift GitOps username; required for Bitbucket integration. Uncomment all 5 instances in `azure-pipelines.yml` |

### ACS and SBOM Variables

| Variable | Description |
|----------|-------------|
| `ROX_CENTRAL_ENDPOINT` | Endpoint for the ROX Central server |
| `COSIGN_PUBLIC_KEY` | Public key for Cosign |
| `TRUSTIFICATION_BOMBASTIC_API_URL` | URL for Trustification Bombastic API (SBOM) |
| `TRUSTIFICATION_OIDC_ISSUER_URL` | OIDC issuer URL for Trustification auth |
| `TRUSTIFICATION_OIDC_CLIENT_ID` | Client ID for Trustification OIDC auth |
| `TRUSTIFICATION_SUPPORTED_CYCLONEDX_VERSION` | CycloneDX SBOM version generated by the system |

### Optional Rekor and TUF Variables

Set these if CI provider runners do not run on the same cluster as the
RHADS-SSC instance:

| Variable | Description |
|----------|-------------|
| `REKOR_HOST` | URL of your Rekor server |
| `TUF_MIRROR` | URL of your TUF service |

## Custom Variable Group Name

If the variable group is not named `tssc`, update `azure-pipelines.yml`:

```yaml
variables:
    - group: <my-variable-group>
```

## Pipeline Permissions

To authorize pipelines to use the variable group:

1. Select the Pipeline permissions tab in the variable group editor.
2. Select Add pipeline.
3. Select the pipelines that require access and authorize them.

## Creating Pipelines

Pipelines are created for both application source and GitOps repositories.

Prerequisites:
- Azure Pipelines variable group with all required variables and secrets
- Active pipelines agent pool with permission for each pipeline
- Source code and GitOps repositories created from RHDH software templates
- Corresponding pool name and variable group referenced in `azure-pipelines.yml`

Procedure:
1. Sign in to your repository.
2. Adjust permissions as needed.
3. Select Approve and install.
4. Select Queued job.
5. Repeat for the GitOps repository.

## Verification

Rerun the latest pipeline. If secrets are applied correctly, the pipeline
completes successfully. Verify that ACS scanning, SBOM generation, and image
signing tasks display expected details.
