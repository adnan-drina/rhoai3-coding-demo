# OCP observability

Thin skill: repo decisions and pitfalls here, product behavior in the linked
monitoring stack 4.22, Cluster Observability Operator (1-latest) and OCP 4.22
sections. Detailed records:
`gitops/stages/010-openshift-ai-platform-foundation/010-observability-operators/README.md`
and `gitops/stages/010-openshift-ai-platform-foundation/010-console-observability/README.md`.

## When to use

- A change touches `010-observability-operators/cluster-monitoring/`, the COO
  folder, or `010-console-observability/monitoring-uiplugin.yaml`.
- A workload needs scraping, an alert rule, or a console/Perses dashboard.
- Prometheus PVCs fill, workers evict pods, or dashboards are empty.

## Procedure

1. Change monitoring ConfigMaps, Subscriptions and dashboards in Git only;
   edit `gen-cost-dashboards.py`, not the generated PersesDashboard YAML.
2. Deploy and validate Stage 010:
   `./stages/010-openshift-ai-platform-foundation/deploy.sh`,
   `./stages/010-openshift-ai-platform-foundation/validate.sh`,
   `./stages/010-openshift-ai-platform-foundation/validate-console-observability.sh`.
3. By hand, after the OpenShift safety guard in `AGENTS.md`:

   ```bash
   oc get cm cluster-monitoring-config -n openshift-monitoring -o jsonpath='{.data.config\.yaml}'
   oc get pvc -n openshift-monitoring; oc get pvc -n openshift-user-workload-monitoring
   oc get uiplugin monitoring -o jsonpath='{.spec}{"\n"}'
   oc apply --dry-run=server -k gitops/stages/040-governed-models-as-a-service/040-maas-platform/observability
   ```

## Pitfalls

- Keep `retentionSize` and the PVC size changed together; the repo values
  (8GB/40Gi, 5GB/20Gi) leave headroom. Check [core storage][core-storage]
  before resizing a live Prometheus volume.
- A rolling `stable` channel can deliver a new COO minor; `deploy.sh` fails
  closed until `check-operator-policy.py` is updated.
- The `docs/TROUBLESHOOTING.md` "MaaS Grafana ..." entries describe a
  retired Grafana path; the repo has no Grafana (see `ocp-grafana-operator`).
- Known symptoms: `docs/TROUBLESHOOTING.md#worker-nodes-evict-pods-after-a-cluster-resume-kubenodeeviction`,
  `docs/TROUBLESHOOTING.md#observability-dashboard-shows-no-dashboards-found`,
  `docs/TROUBLESHOOTING.md#usage-dashboard-shows-zeros-or-gaps-limitador-podmonitor-churn`,
  `docs/TROUBLESHOOTING.md#observability-dashboards-show-empty-gpu-inter-token-latency-or-error-rate-panels`.
