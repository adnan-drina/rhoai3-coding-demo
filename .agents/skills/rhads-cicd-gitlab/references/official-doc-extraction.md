# Official Doc Extraction

Use this extraction to keep GitLab CI integration content grounded in official
RHADS-SSC 1.9 sources.

## Product Overview

Red Hat Advanced Developer Suite - software supply chain (RHADS-SSC) integrates
with GitLab CI to perform vulnerability scanning, image signing, and
attestation generation. Pipelines require secrets configured as GitLab CI/CD
variables.

## UI Configuration

### Adding Masked Secrets

In GitLab Settings > CI/CD > Variables:

1. Select Add variable.
2. Enter Key and Value.
3. Under Flags, select Mask variable.
4. Select Add variable.

### Adding Unmasked Variables

1. Select Add variable.
2. Enter Key and Value.
3. Under Flags, do not select Mask variable.
4. Select Add variable.

## Secrets (Masked)

### Image Registry and GitOps Secrets

| Variable | Description |
|----------|-------------|
| `QUAY_IO_CREDS_PSW` | Password for accessing your Quay repository |
| `ARTIFACTORY_IO_CREDS_PSW` | Password for accessing your JFrog Artifactory repository |
| `NEXUS_IO_CREDS_PSW` | Password for accessing your Sonatype Nexus repository |
| `GITOPS_AUTH_PASSWORD` | Token the system uses to update the GitOps repository for newly built images |

### ACS and SBOM Secrets

| Variable | Description |
|----------|-------------|
| `ROX_API_TOKEN` | API token for accessing the ROX server |
| `COSIGN_SECRET_PASSWORD` | Password for Cosign signing key |
| `COSIGN_SECRET_KEY` | Private key for Cosign |
| `TRUSTIFICATION_OIDC_CLIENT_SECRET` | Client secret for Trustification Bombastic API OIDC auth |

All credentials are already Base64-encoded from `private.env` and do not
require additional encoding.

## CLI Configuration

### env_vars.sh

Export credentials including GitLab-specific tokens:

```bash
export MY_GITLAB_TOKEN="your_gitlab_token_here"
export MY_GITLAB_USER="your_gitlab_username_here"
export QUAY_IO_CREDS_USR="your_quay_username_here"
export QUAY_IO_CREDS_PSW="your_quay_password_here"
# ... (all other credentials)
```

### glab-set-vars Script

The script uses the GitLab API to set variables. The `setVars` function:

1. Deletes existing variable (to allow value updates).
2. Creates the variable via POST to `/api/v4/projects/$PID/variables`.
3. Defaults to `masked=true`; pass `false` as third argument for unmasked.

```bash
source env_vars.sh
chmod +x glab-set-vars
./glab-set-vars your_repository_name
```

## Self-Hosted GitLab Runner Requirements

### Security Context Constraint (SCC)

Required when using self-hosted GitLab runners on OpenShift (whether using
self-hosted GitLab or gitlab.com):

```yaml
apiVersion: security.openshift.io/v1
kind: SecurityContextConstraints
metadata:
  name: gitlab-ci-sa-scc
  namespace: gitlab-runner
allowHostPorts: false
allowPrivilegeEscalation: true
allowPrivilegedContainer: true
allowedCapabilities:
  - SETFCAP
  - MKNOD
defaultAddCapabilities: null
fsGroup:
  type: RunAsAny
priority: 5
readOnlyRootFilesystem: false
requiredDropCapabilities:
  - KILL
runAsUser:
  type: MustRunAs
  uid: 0
seLinuxContext:
  type: RunAsAny
supplementalGroups:
  type: RunAsAny
users:
  - system:serviceaccount:gitlab-runner:gitlab-ci-sa
volumes:
  - configMap
  - downwardAPI
  - emptyDir
  - persistentVolumeClaim
  - projected
  - secret
```

Apply and verify:

```bash
oc apply -f gitlab-ci-scc.yml
oc get scc gitlab-ci-sa-scc
```

The namespace in the `users` field may need adjustment for your environment.

### Maximum Artifact Size

Required for self-hosted GitLab instances. Adjust the maximum artifact size
limit in GitLab admin settings to accommodate pipeline artifacts.

## Verification

Rerun the last pipeline run or commit a minor change to trigger a new run.
If secrets are applied correctly, the pipeline completes successfully.
