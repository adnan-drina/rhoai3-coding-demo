## Preservation-first handoff and deployment order

1. **Review and capture before any write.** Render core from its exact immutable bridge revision and receiving Stage 050 source. Capture seven authored MLflow resource UIDs/full specs, native generated ownership, PVC/PV/OBC/credential metadata, component state, and tenant MLflow experiment/run IDs plus content digests through authenticated read-only APIs. Existing artifacts are preserved; any targeted before/after sample is a later explicit functional check. Compare source-declared spec with served defaults without broad ignores. Abort foreign owners, missing/partial DB storage/credentials, unexpected schemas or API errors.
2. **Protect, then omit.** A narrow one-time transition based on the pinned core bridge first adds `Prune=false,Delete=false` to the seven MLflow customer resources and waits for exact revision/path successful operation plus readback. Next omit only those seven from core while keeping DSC MLflow Managed and every other core object identical. Merge exact DSC `mlflowoperator`/`trustyai` ignores and the exact sandbox tenant-label ignore; no HEAD/base repoint, wildcard ignore or global prune disable. Core currently lacks those delegations. Confirm the omission actually reconciled, including source path when phases share a SHA. Compare UIDs/specs/data before receiving adoption.
3. **Ordinary Stage 050 Application first.** Its first modifying action adopts the unchanged seven resources after the separate reviewed transition. Native MLflow owns generated workloads; OBC owns generated credentials. Credentials remain runtime inputs, with narrow target-data ignores where receiving Git authors a skeleton. No retained Secret value goes through Git, logs or last-applied annotations. Adoption must preserve the original storage, database credentials and MLflow records.
4. **Native components and fresh EvalHub inputs.** RHOAI 3.5.1 enables TrustyAI; keep MLflow Managed. Wait native component/CRD readiness, then create/reuse the dedicated EvalHub DB Secret via guarded runtime setup before PVC/StatefulSet wave. PostgreSQL is the chosen durable design, not an unconditional EvalHub API requirement (SQLite is nonpersistent). Wait DB current readiness. This sequencing avoids the existing clean-before-App allowance accepting storage created before a missing Secret.
5. **Tracking before EvalHub.** Verify current MLflow and unchanged artifact path, publish its native HTTPS tracking URI, then create EvalHub. `MLFLOW_TRACKING_URI` enables optional tracking; do not claim tracking if absent. Native controller owns projected token/service CA/job SA and tenant bindings. Verify actual server/job workspace scope before defining run correlation. Do not relabel the server namespace as the sandbox tenant.
6. **Service acceptance, then explicit evaluation.** Real persona discovery/authorization can pass with models/GPU at zero. Select a proven chat-capable benchmark and only later restore agreed compute for one explicitly authorized run. User owns dashboard checks; API/backend proof is labeled separately.

Abort on any UID/spec/data/bucket/config drift or unexpected operator change. Before omission, leave core ownership intact on failure. After omission, keep protected resources and MLflow Managed; do not blindly restore a core render that competes with adopted Stage 050 ownership. Rollback requires the reverse reviewed ownership transfer, preserving all records/storage/Secrets. Never delete a CR/PVC/OBC or replay old DB credentials as a rollback shortcut.
