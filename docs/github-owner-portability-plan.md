# Plan: GitHub-owner portability (Level 2)

**Status:** proposed — for review before execution.
**Scope:** make the demo deployable from any GitHub org, not just `adnan-drina`.
**Companion (done):** registry portability — the coolstore deployment image now
follows `IMAGE_REGISTRY` via the `patch-image-registry` PostSync hook (commit
`e0d1633`). This plan covers the remaining hardcoded owner references.

## Current state

`adnan-drina` is referenced across GitOps + scripts, pointing at **5 repos**:

| Repo | Refs | Role | Portable today? |
|------|------|------|-----------------|
| `rhoai3-coding-demo` | 15 | the demo GitOps repo itself | **Yes** — app-of-apps `repoURL` is templated from `GIT_REPO_URL` by each `deploy.sh`, and `generate-rhdh-catalog` derives owner/name from the live Argo `repoURL` (regex at job L145/164). |
| `coolstore-inventory-service` | 12 | brownfield app the demo builds & the exercise pushes to | No — hardcoded |
| `agentic-quarkus-scaffold` | 10 | golden-path scaffolder template | No — hardcoded |
| `migiq-spring-boot-sample` | 3 | Stage 080 migration source | No — hardcoded |
| `getting-started-ai-coding` | 3 | onboarding workspace repo | No — hardcoded |

The **demo repo** is already portable. The work is the **4 source repos**, which a
deployer must be able to point at their own forks.

## Prerequisite the deployer accepts

The 4 source repos are real Git repositories the demo clones, builds, scaffolds
from, and **pushes to during the exercise**. A portable deploy therefore requires
the deployer to **fork these 4 repos into their own org** (the exercise pushes
commits and the scaffolder publishes new repos — both need write access they
cannot have on `adnan-drina/*`). `scripts/bootstrap-golden-repos.sh` already
creates/tops these repos; extend it to target `GITHUB_OWNER`.

## New knob

Add `GITHUB_OWNER` to `.env` (single owner for all forks; the demo repo keeps
using `GIT_REPO_URL` so a deployer can host GitOps and source under different
orgs if they wish). Wire it in two places:

1. **`deploy.sh` pre-flight** (Stage 050 + any stage that clones a source repo):
   `require_env GITHUB_OWNER "GitHub org/user that owns your forks of
   coolstore-inventory-service, agentic-quarkus-scaffold, migiq-spring-boot-sample
   and getting-started-ai-coding. The pipelines clone from here, the scaffolder
   publishes here, and the exercise pushes here."` — reuse the helper added in
   `lib.sh` (commit `1b01833`).
2. **A `demo-repo-config` ConfigMap** in `app-platform-build`, written by
   `deploy.sh` from `.env` (`GITHUB_OWNER`, and the already-used `IMAGE_REGISTRY`),
   so in-cluster hooks/tasks can read it — same source-of-truth pattern as
   `app-platform-build-config`.

## Substitution mechanism (per file category)

GitOps manifests are static YAML Argo pulls from Git, so they cannot read env
vars directly. Two mechanisms already exist in the repo; reuse them rather than
introduce a third:

- **A. Placeholder + sync-hook substitution** (the `generate-rhdh-catalog`
  pattern — it already rewrites `__RHOAI3_DEMO_REVISION__` and route placeholders
  in the catalog). Put `__GITHUB_OWNER__` in the manifests and have a Sync hook
  substitute it from the `demo-repo-config` ConfigMap.
- **B. Owner already derived from Argo `repoURL`** — `generate-rhdh-catalog`
  regex. Extend where a manifest's owner should track the *GitOps* repo owner.

Recommended split:

| Files | Mechanism |
|-------|-----------|
| `rhdh/catalog/all.yaml` | already regenerated by the catalog hook — add `__GITHUB_OWNER__` for the 4 source-repo links and substitute in that job (mechanism A, extends existing job). |
| `rhdh/templates/agentic-quarkus-scaffold/template.yaml`, `skeleton/catalog-info.yaml` | scaffolder `repoUrl`/owner param → `__GITHUB_OWNER__`; substitute via the catalog/config hook (A). |
| `pipelines/build/triggers.yaml`, `appproject-scaffolded.yaml`, `project-provisioner.yaml` | `repoURL`/owner → `__GITHUB_OWNER__` (A). |
| `devspaces/agentic-workspace.yaml`, `workspaces.yaml`, `migiq/agentic/agentic-migration-workspace.yaml` | project `git.remotes` URL → `__GITHUB_OWNER__` (A). DevWorkspace edits also need the workspace recreated (they are immutable once started). |
| `coolstore/kustomization.yaml` | comment only — update text. |
| `stages/**/deploy.sh`, `scripts/*.sh` | replace literal `adnan-drina` with `${GITHUB_OWNER}` (shell already loads `.env`). |
| `stages/**/README.md`, `*-exercise.md`, `validate.sh` | docs: replace with `${GITHUB_OWNER}` / a documented placeholder; validate.sh derives from env. |

## Concrete steps

1. `lib.sh` / `deploy.sh` (050 + 080): `require_env GITHUB_OWNER`; write
   `demo-repo-config` ConfigMap (`GITHUB_OWNER`) into `app-platform-build`.
2. Introduce `__GITHUB_OWNER__` placeholders in the GitOps files above.
3. Extend `generate-rhdh-catalog` (or add a sibling `substitute-repo-owner`
   Sync hook) to replace `__GITHUB_OWNER__` from `demo-repo-config`, and add a
   leftover-placeholder guard (`grep -q __GITHUB_OWNER__ && fail`) — same guard
   style the catalog job already uses.
4. Scripts: `adnan-drina` → `${GITHUB_OWNER:?set GITHUB_OWNER in .env}`.
5. `bootstrap-golden-repos.sh`: create/fork the 4 source repos under
   `GITHUB_OWNER`; document the one-time fork step in `README.md`.
6. Validation: a check that **no `adnan-drina` literal survives in rendered
   manifests** (`oc kustomize … | grep -q adnan-drina && fail`) and that
   `demo-repo-config` carries `GITHUB_OWNER`. Add to `stages/050/validate.sh`.

## Risks / call-outs

- **Fork drift:** forks must track the upstream golden branches (`golden`,
  `main`) or the exercise diverges. Document a `git remote add upstream` + sync
  note, or have `bootstrap-golden-repos.sh` seed forks from the upstream tags.
- **Webhooks are per-fork:** each forked source repo needs its own webhook →
  `app-platform-listener` with `GITHUB_WEBHOOK_SECRET`. `bootstrap-golden-repos.sh`
  should register it.
- **Scaffolder publishes to `GITHUB_OWNER`:** the golden-path template creates
  new repos there; the token in `rhdh-github` must own that scope.
- **DevWorkspace immutability:** owner changes in workspace specs require the
  workspace to be recreated, not just re-synced.
- **Docs are load-bearing:** the exercise markdown embeds clickable repo URLs;
  leaving a stray `adnan-drina` there sends users to the wrong repo. The rendered
  no-literal check should also scan `stages/**/*.md`.

## Effort

~15 GitOps/script files + 1 new/extended sync hook + `bootstrap-golden-repos.sh`
+ validation + docs. Medium. Best landed as one reviewed PR after the fork step
is documented, since a half-applied owner change breaks the exercise chain.
