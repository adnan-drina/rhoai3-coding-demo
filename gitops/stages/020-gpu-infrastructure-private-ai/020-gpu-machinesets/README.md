# GPU MachineSets (`020-gpu-machinesets`)

This Application declares the AWS GPU worker pools as Machine API MachineSets. There are two pools: RTX PRO 6000
Blackwell (`g7e.2xlarge`, the default pool), and L40S (`g6e.2xlarge`). Git owns
each pool's shape (instance type, disk, labels, taint); the GPU pause/resume scripts own the replica count. All GPU
workloads in Stages 030 to 050 run on nodes from these pools.

## Why

OpenShift adds GPU nodes on AWS by copying an existing compute MachineSet, changing its name, labels and instance
type, and creating it [1]. Keeping the result in Git makes the pool shape reviewable and reproducible, instead of
creating it from a hook at sync time. GPUs are expensive, so the demo parks the pools at zero and scales them by
hand [2]; Argo CD therefore ignores `spec.replicas`.

A Machine API MachineSet launches in exactly one subnet and zone and never retries another zone. To reach
whichever zone has capacity, the RTX PRO 6000 pool has one MachineSet per `us-east-2` zone (pool table in
the generator).

The pools are their own Application because they hold cluster-specific data and must never be pruned or deleted
with the rest of the stage.

## What

| Kind | Name | Namespace | Purpose |
|---|---|---|---|
| MachineSet | `<infra-id>-gpu-us-east-2a` | `openshift-machine-api` | L40S pool: `g6e.2xlarge`, label `cluster-api/accelerator: nvidia-gpu`, Git replicas 0 |
| MachineSet | `<infra-id>-gpu-rtxpro6000-us-east-2{a,b,c}` | `openshift-machine-api` | RTX PRO 6000 pool (default): `g7e.2xlarge`, label `cluster-api/accelerator: nvidia-rtxpro6000`, `demo.rhoai.io/gpu-pool: rtxpro6000`, Git replicas 0 |

Common to all four: 200 GB encrypted `gp3` root volume; node labels `cluster-api/accelerator` and
`node-role.kubernetes.io/gpu`; node taint `nvidia-gpu-only:NoSchedule`; resource annotation
`argocd.argoproj.io/sync-options: Prune=false,Delete=false`; provider references (AMI, subnet and security group
filters, IAM instance profile, `worker-user-data`, `aws-cloud-credentials`, tags) copied from the active CPU worker
pool in the same zone, named in the `demo.rhoai.io/source-machineset` annotation.

Other files:

| File | Purpose |
|---|---|
| `kustomization.yaml` | Lists the two MachineSet files |

Objects not in Git (Machine API-owned): Machines, Nodes, AWS instances, and the live `spec.replicas` value. The
L40S file sets the `machine.openshift.io/GPU`, `vCPU` and `memoryMb` annotations; for the RTX PRO 6000
MachineSets the Machine API fills them in (live: 1 GPU, 8 vCPU, 65536 MiB).

## How

- **Generation.** `stages/020-gpu-infrastructure-private-ai/deploy.sh --generate-machinesets <cpu-machineset> --write` generates both pool files
  from one pool table in the script. It checks that the source is an active native AWS CPU worker pool on amd64
  with the cluster's infrastructure name, then derives each MachineSet from the active CPU worker pool of its own
  zone: the L40S pool in the source's zone, the RTX PRO 6000 pool in every zone (it refuses a zone with
  several active worker pools). Every MachineSet gets its instance type, accelerator and pool labels, 0 replicas,
  a 200 GB gp3 encrypted disk and the taint. It writes the replica exception for every generated MachineSet to
  the Application manifest, so regenerating never drops one. Without `--write` it
  prints the MachineSets for review.
- **Disk size.** 200 GB because a 100 GB worker hit kubelet `DiskPressure` while pulling a ~36 GB model image
  (comment in the generator).
- **Taint and labels.** `nvidia-gpu-only:NoSchedule` keeps non-GPU pods off the nodes. The `ClusterPolicy`
  tolerates it, and each Kueue GPU flavor tolerates it and selects its pool by `cluster-api/accelerator`. OpenShift
  documents `cluster-api/accelerator` as the GPU label for the cluster autoscaler [1]; no `ClusterAutoscaler` is
  used here, so the label only serves Kueue and the scripts.
- **Replica delegation.** `ignoreDifferences` on `/spec/replicas` for all four MachineSets, with
  `RespectIgnoreDifferences=true` so a sync does not reset a scaled pool. This applies only to MachineSets that
  already exist; a new MachineSet is created with the Git value [3], which is 0 for every pool, so a new cluster
  starts no GPU workers until a pool is scaled. `deploy.sh --gpus 1` scales one
  RTX PRO 6000 MachineSet (default zone `us-east-2a`, 1 replica) or, with `GPU_POOL=l40s`, the L40S MachineSet,
  and `--gpus 0` scales every pool to zero. To test AWS capacity, scale one zone at a time to 1 and back to 0
  by hand (the former `gpu-capacity-probe.sh` is in git history at `82092e01`).
- **Delete protection.** `Prune=false,Delete=false` keeps a MachineSet when it is removed from Git or when the
  Application is deleted [3]. Removing a pool is a manual, reviewed step (see `docs/OPERATIONS.md`, Stage 020).
- **Deploy checks.** `deploy.sh` requires `machineset-gpu.yaml`. For every generated MachineSet it verifies 0
  replicas in Git, that the provider spec still equals its active source pool with only type and disk changed, and
  that the Application manifest has its replica exception. It refuses a MachineSet with a foreign owner or no
  `020-gpu-machinesets` tracking, then deploys the components with `stage-apps.sh deploy 020`.
- **Secrets.** The MachineSets reference the platform's `aws-cloud-credentials` and `worker-user-data` Secrets by
  name; no secret value is in Git.
- **Cluster-specific values.** Infrastructure name, AMI, region and zones, subnet and security group filters, IAM
  instance profile and AWS tags come from the source CPU pool. A new cluster needs regenerated files.

## Validation

`validate.sh` checks that every MachineSet labelled `nvidia-gpu` or `nvidia-rtxpro6000` has its reviewed instance
type, is current, and has `readyReplicas` equal to `spec.replicas`; it prints the replicas per pool. It then
checks that every Ready GPU node allocates one `nvidia.com/gpu`, has the GFD product label of its pool, and has the
`nvidia-gpu-only` taint. With the pools parked at zero, the node checks fail by design.

```bash
oc get machinesets -n openshift-machine-api -L cluster-api/accelerator
stages/020-gpu-infrastructure-private-ai/validate.sh
```
